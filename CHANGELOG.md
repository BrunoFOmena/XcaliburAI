## [Unreleased]

### Added
- ECHOLAS agents (#9): `echolas_executor` (plans with input validation, runs only after confirmation, refuses invalid inputs and explains each error) and `echolas_interpreter` (reads results, cannot run anything), with instructions versioned in `prompts/*.md` and their own tool lists. Read-only result tools `echolas__summarize_run`, `summarize_vcf`, `read_pca` and `read_tree` (standard library only): samples, variants by type and filter, per-sample genotypes, PCA eigenvalues and shares of the computed PCs, PC1/PC2 per sample, tree splits with SH-aLRT/UFBoot support, and caveats decided by the tool (few samples, missingness, unsupported splits, branch lengths without ascertainment correction, diploid calling). Tested on outputs of the synthetic dataset (`tests/data/echolas_outputs`).
- Grounded numbers: tools can be marked `grounded=True`; after a turn that used one, every number in the answer must match a number in those results (or the user's message) at the precision shown. An answer that fails is sent back once for correction, then returned with a warning listing the untraced numbers (`LoopResult.ungrounded_numbers`). `xcalibur chat` adds every installed domain agent's instructions to its system prompt.
- ECHOLAS input validation (#6): before `plan` or `run`, `reference` must hold exactly one uncompressed `.fna`/`.fa`/`.fasta` genome, and `raw_data` only gzip-compressed FASTQ files with complete `_R1`/`_R2` (or `_1`/`_2`) pairs or single-end files, one layout per sample. The rules mirror how the pipeline names samples and mates, so cases it would accept silently and get wrong (a missing mate read as single-end, a sample with both layouts, two files for the same mate, uncompressed FASTQ skipped) fail with a message that names the file and the fix. Read-only: names, sizes and the gzip signature. New core hook `DomainPlugin.validate_inputs` returning an `InputReport` (errors, warnings, detected samples); errors stop the plan or run with `invalid_inputs` (exit 2), and the plan carries the report as `input_check`. The CLI prints one line per input problem, and with `--json` the error carries the structured `errors` list (`code`, `message`, `input`, `path`, `sample`); an unreadable folder is an input error, not a crash.
- End-to-end smoke test (#11): `tests/data/make_synthetic.py` writes a deterministic synthetic dataset (3 contigs of 7.5 kb in total, 6 paired-end samples in two clades, known homozygous SNPs and indels; nothing from real sequencing), and `tests/e2e/` runs the full ECHOLAS pipeline on it, checking that the final VCF holds exactly the inserted variants with the right genotypes and that PCA and tree separate the clades. Opt-in with `pytest -m e2e` (`make e2e`); `e2e` CI job after `lint`/`test`, with conda/Nextflow cache, a timeout and the run uploaded on failure, skipped for documentation-only PRs into `homolog`. New `test` profile in the ECHOLAS `nextflow.config` that only caps resources (2 CPUs, 6 GB, 30 min per process).
- `xcalibur run` and `xcalibur plan` accept `--profile NAME` (comma-separated), which overrides the domain's default workflow profile; `plan_run`/`run_pipeline` take an optional `profile` too, names cannot start with `-`, and the chat confirmation shows the profile on its own line (#11).
- `xcalibur chat` and `xcalibur run` (#10). `chat` talks to the agent runtime: it shows the full plan (domain, parameters, inputs, run directory, command) and asks before running (`--yes` skips the question), has the session commands `/help`, `/status`, `/runs` and `/exit`, survives Ctrl+C during an answer, records tool calls in `<workspace>/sessions/<id>/audit.jsonl` and prints one JSON object per answer with `--json`. `run` validates and runs a domain without the LLM, streams the workflow log to stderr while it runs, and with `--json` prints `run_id`, status and paths; `--dry-run` is the same as `plan`. Exit codes: 0 success, 1 execution failure, 2 wrong usage or invalid parameters, 130 interrupted. Terminal colour follows the project's red palette and is off with `--no-color`, `NO_COLOR` or when output is not a terminal. The CLI stays on `argparse` (no new dependency).
- Agent runtime (#8): `AgentLoop` with tool calling, a step limit with a stated stop reason, tool errors returned to the model as structured results, long results truncated and saved to a file, and every tool call recorded in the session (`audit.jsonl` when the session has a directory). Typed tools (`Tool`, Pydantic input models that reject unknown arguments) and a `ToolRegistry`; core tools `list_domains`, `describe_domain`, `plan_run`, `run_pipeline`, `get_run_status` and `read_results`; domains contribute tools through `DomainPlugin.tools`. `run_pipeline` runs only after the confirmation policy approves the exact command (denied by default), and refuses if the command changed after approval. An interrupted tool call still gets a result, so the history stays valid. `LLMRouter` with fallback to the `KeywordRouter`. `FakeProvider` for tests without network. Contract documented in `docs/AGENT_RUNTIME.md`.
- Anthropic LLM provider (optional extra `xcalibur-ai[anthropic]`, official SDK `anthropic>=2.11,<3`): system prompt, tool calls and streaming in the `LLMProvider` interface, bounded retries, clear auth/limit/network errors without the key, refusal handling with server-side fallback (#7).
- `xcalibur init` (interactive or `--non-interactive`) saves the provider, model and the NAME of the key variable to `xcalibur.yaml`; `xcalibur check-llm` tests the connection (#7).
- ECHOLAS pipeline imported into `xcalibur-echolas` (`main.nf`, 5 modules, scripts, `nextflow.config`) with its MIT notice. Input directories are now the `raw_data` and `reference` params.
- `issue-link` check: every PR must close an open issue with a closing keyword (required on `main` and `homolog`).
- Nextflow adapter executes runs for real: per-run directory `runs/<run_id>/`, log and HTML report, `run-<id>.json` provenance (engine version, container, return code), `-resume`, SIGINT/SIGTERM cancellation and a clear error when `nextflow` is missing (#5).
- Versioning rules (`docs/VERSIONING.md`) and a test that enforces version consistency.
- Issue template following the project standard, and the issue title-prefix convention in `CONTRIBUTING.md`.

### Fixed
- Agent runtime edge cases (#43): when only the audit write fails, the model gets the tool's real result instead of `interrupted` (the exception still reaches the caller); an `interrupted` result says whether the tool had started (`"started": true`: it may have run, check before retrying) or not; every interrupted call is audited even when call ids repeat in a step. The truncation note always fits in `max_result_chars` (minimum 200): the path is made relative to the session directory or left out when it does not fit, and a result that cannot be saved is still sent as a preview with `save_error`. A result nested too deep or whose text form fails is an `internal_error` instead of ending the turn. The confirmation policy gets a copy of the plan, so it cannot change what `run_pipeline` compares. Saved results are created exclusively, so two sessions in one directory never overwrite each other.
- LLM configuration follow-ups of #7 (#40): a workspace `xcalibur.yaml` cannot raise `max_tokens` above 64000, `max_retries` above 5 or `timeout` above 600 s (clear error pointing to the user configuration or `--config`); `timeout` is at most 86400 s in any configuration. `xcalibur check-llm` prints the configuration file, whether it is a workspace file, and the model, effort and limits in use; `check-llm` and `chat` warn on stderr when a workspace file replaces an existing user configuration, and the chat `/status` shows the file. `xcalibur init --workspace` no longer asks for the key variable (only the standard one is allowed) and refuses `--base-url` or another `--api-key-env` before prompting; in any mode, a key pasted into `--api-key-env` is refused before the first prompt instead of being shown as its default. The replacement warning appears only when the workspace file exists. A huge integer `timeout`, a number over 4300 digits or an invalid date in the file is a clear error (exit 2) instead of an unexpected error (exit 1), and a workspace with an unknown provider says so instead of "may only use None".
- Audit follow-ups of #21 (#32): a `run_id` must start with a letter or digit (`-x` is rejected before touching the disk, so an id from the CLI is never read as an option; the agent tools and the CLI share the same pattern, so `xcalibur run --run-id=-x` exits 2 with `invalid_arguments`); the attempt number is claimed by creating its record exclusively, so two runs of the same `run_id` started at once never share an attempt; the old Nextflow report is set aside before the process starts and put back if it cannot start; a test checks that the engine gets `/dev/null` as stdin.
- `branch-policy`: a PR into `homolog` now fails if it brings any commit of `main` that `homolog` does not have (e.g. a work branch that merged `main`), not only when the head is named `main` or `promote/*`; the error lists the offending commits. Logic in `.github/scripts/check-homolog-pr.sh`, covered by `tests/test_branch_policy.py` (#33).
- Nextflow run cancellation is robust (#20): SIGINT/SIGTERM handlers are installed before anything starts and only request cancellation, so a signal right after the subprocess starts, before it starts, or a second Ctrl+C during cleanup can no longer leave Nextflow running; the run is marked `cancelled` and `run-<id>.json` is written. A safety net stops the process group if waiting fails for any other reason, and after Nextflow exits (whatever the outcome) anything still left in the run's process group, such as a conda environment build Nextflow did not stop, is terminated (SIGTERM, then SIGKILL after 5 s). Execution is POSIX-only: on platforms without process groups (Windows) a real run raises `UnsupportedPlatformError` with a clear message (`run_pipeline` returns `unsupported_platform`) instead of an `AttributeError`; planning still works.
- ECHOLAS `plot_pca.R` no longer calls `read_table2` (gone from readr 2) and reads any number of PCs, so the PCA plot works with fewer than 10 samples (#11).
- ECHOLAS could not build the PCA environment with conda: `r-base` and the R packages now come from `conda-forge` (`bioconda::r-base` does not exist) (#11).
- ECHOLAS `nextflow.config` enables conda with `conda.enabled = true` instead of `process.conda = true`, which made processes without their own environment ask for a package named `true` (#11).

### Changed
- ECHOLAS reads sample and mate names robustly (#63): the mate tag is read only at the end of the file name (`_R1`/`_R2`, `_1`/`_2`, Illumina `_R1_001`) and in any case, and the rest of the name, dots included, is the sample, so `A_r1`/`A_r2`, `A.v2_R1`, `SRR_123_1` (now `SRR_123`, was `SRR23`) and `S_1_R2` (was read as R1) are understood correctly; `.fq.gz` and any-case extensions are read. `main.nf` passes the mate with each file to `trimming_qc.nf`. The input validation uses the same two patterns, and a test runs them in Nextflow and Python on the same names. Lanes are not merged: samples that differ only by `_L001`/`_L002` run apart, with a warning. Names in the usual form (`<sample>_R1/_R2`, `<sample>_1/_2`, `<sample>.fastq.gz`, no dots) keep the same sample names.
- An invalid `xcalibur.yaml` is reported on one line with the 1-based line and column, e.g. `error: xcalibur.yaml:2:1: invalid YAML (expected the node content, but found '<stream end>')`, instead of PyYAML's multi-line text with a `^` marker; still exit code 2, no traceback (#39).
- The provenance record is written when the run starts, with `status: "running"`, and rewritten with the outcome at the end (an unexpected error after it is created marks it `failed` before being re-raised, so it never stays `running`); `read_results` refuses a run that is still running (#32).
- `xcalibur plan` shares the validation of `run` (inputs resolved against `--workspace`) and gains `--json`, `--run-id`, `--workspace` and `--nextflow`; a malformed `KEY=VALUE` now exits with code 2 and the CLI never prints a traceback (#10).
- `Message` carries tool calls (assistant) and tool results (user), sent to Anthropic as `tool_use`/`tool_result` blocks; `AgentSpec` gains `instructions` and `tools`; `RunRecord.filename_for` is public (#8).
- Every PR (work and promotion) is merged with a merge commit; squash and rebase merges are no longer used (#35).
- Promotion flow: `main` now receives a PR directly from `homolog`, merged with a merge commit; the `promote/*` branches and the cherry-pick `-x` requirement are gone. The `branch-policy` check enforces it (#26).
- `run_id` is validated (`^[A-Za-z0-9_-]+$`) in `RunSpec`, `RunRecord` and `Workspace.run_dir`; invalid ids raise `ValueError` before touching the disk (#21).
- Each attempt of a run keeps its own provenance record (`run-<id>.json`, then `run-<id>.attempt-<n>.json`, with an `attempt` field); the previous HTML report is removed only when a resume actually starts; Nextflow no longer inherits stdin; `inputs` records absolute paths (#21).
- Governance: the CTO (@BrunoFOmena) is the sole code owner; the CEO (@MCamposDA) needs the CTO's approval. README, CONTRIBUTING and CODEOWNERS updated.
